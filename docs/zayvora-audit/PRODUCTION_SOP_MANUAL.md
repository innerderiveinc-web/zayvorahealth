## 2. SOP-01: Zero-Downtime Deployment & Database Migration SOP

### 2.1 Purpose
Defines the mandatory procedure for deploying new microservice releases and schema migrations to production without service interruption or database locking.

### 2.2 Pre-Deployment Checklist
1. All unit, integration, and clinical continuum tests passing (219/219 master tests, 253/253 verification tests).
2. Point-in-Time snapshot taken and verified via `python3 database/dr_backup_restore.py`.
3. Vault secrets injected and validated.
4. Kubernetes cluster resources verified (`kubectl top nodes`).

### 2.3 Deployment Execution Sequence
```bash
# Step 1: Pre-flight snapshot drill
python3 database/dr_backup_restore.py

# Step 2: Execute non-locking database migrations
python3 database/migrations/migrate.py upgrade all

# Step 3: Rolling update of Kubernetes pods via Helm 3
helm upgrade --install zayvora infrastructure/helm/zayvora \
  --namespace zayvora-production \
  --values infrastructure/helm/zayvora/values.yaml \
  --set global.environment=production \
  --wait --timeout 5m

# Step 4: Validate canary pod health probes
kubectl get pods -n zayvora-production -l app.kubernetes.io/part-of=zayvora-health
```

### 2.4 Post-Deployment Health Gate
- Verify `/health/live` and `/health/ready` on all microservices.
- Execute automated smoke test suite: `python3 tests/run_comprehensive_verification_audit.py`.

## 3. SOP-02: Security Incident Response & PHI Breach Management SOP

### 3.1 Purpose
Establishes protocol for detecting, isolating, and reporting security anomalies, unauthorized access attempts, or potential Protected Health Information (PHI) compromise.

### 3.2 Severity Matrix
- **Tier 1 (Critical)**: Unauthorized decryption attempt, RLS cross-tenant breach, or Merkle audit ledger anchor tampering.
- **Tier 2 (High)**: Gateway rate-limiter sustained threshold violation (> 50 req/sec blocked).
- **Tier 3 (Medium)**: AI prompt injection or guardrail evasion attempt.

### 3.3 Incident Containment Procedures
1. **Immediate Revocation**: Invalidate compromised JWT or session tokens via Identity Service Redis blacklist.
2. **Cryptographic Key Rotation**:
   ```python
   # Invoke clinical crypto envelope key re-wrapping
   from services.clinical.app.core.crypto import rotate_kek
   rotate_kek(old_kek_id="KEK-2026-A", new_kek_id="KEK-2026-B")
   ```
3. **Forensic Audit Ledger Extraction**:
   Extract Merkle block logs via `CryptographicAuditLedger.verify_chain_integrity()` to identify tainted transaction IDs.
4. **Statutory Regulatory Notification**:
   Notify CERT-In and Data Protection Board within 6 hours per Indian Digital Personal Data Protection Act (DPDPA) & DISHA regulations.

## 4. SOP-03: Clinical Prescribing Authority & Schedule E(1) Mudabbar SOP

### 4.1 Purpose
Ensures that no clinical prescription, compound nuskha, or regimen is finalized or dispensed without explicit, non-delegable qualified human clinician authorization.

### 4.2 Statutory Golden Rules
1. **AI Non-Delegability Invariant**:
   - The AI Copilot (`Hakeem Sahab`) is strictly an informational clinical decision support system.
   - Prescriptions generated by AI or ambient scribe default to `safe_to_lock = False`.
   - The status cannot transition to `active` without a registered Tabeeb's authenticated digital signature and AYUSH Council Medical Registration Number.
2. **Schedule E(1) Mudabbar Poison Rule**:
   - Classical Unani toxic botanicals (*Kuchla/Strychnos nux-vomica*, *Suranjan Talkh/Colchicum luteum*, *Bhilawa/Semecarpus anacardium*, *Afeem/Papaver somniferum*) cannot be allocated in pharmacy dispensary without certified Mudabbar (detoxification) batch documentation.
   - Database constraint `chk_schedule_e1_mudabbar` strictly blocks unpurified batch entries.

### 4.3 Clinician Approval Workflow
1. Tabeeb reviews draft Nuskha in Next.js Clinician Desk.
2. System evaluates drug-herb interaction matrix (>30 rules) and patient organ-axis biomarkers.
3. If Badal (substitute) herb is used, posology conversion factor is automatically applied per *Makhzan-ul-Adwiya*.
4. Tabeeb reviews posology, checks patient allergies, signs off with credentials, and sets `safe_to_lock = True`.

## 5. SOP-04: Adverse Drug Reaction (ADR) Pharmacovigilance & ICH E2B(R3) SOP

### 5.1 Purpose
Outlines protocol for documenting, investigating, and reporting suspected adverse drug reactions resulting from Unani formulations or herb-drug interactions.

### 5.2 ADR Reporting Protocol
1. **Clinical Intake**: Tabeeb or Pharmacist records adverse symptom in Patient 360 / Care Plan module.
2. **Automated Severity Scoring**: System computes WHO-UMC causality score and Naranjo algorithm probability.
3. **ICH E2B(R3) XML Export**:
   - Trigger `POST /api/v1/care-plans/pharmacovigilance/export-e2b`.
   - System generates standardized XML with MedDRA Lower Level Terms (LLT) and pseudonymized patient demographic attributes.
4. **National PVPI / AYUSH Submission**:
   - Serious adverse reactions (death, life-threatening, hospitalization) must be submitted to the National Pharmacovigilance Centre for AYUSH (NPCA) within 15 calendar days.
