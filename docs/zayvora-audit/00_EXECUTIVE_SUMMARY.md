### 2. Evidentiary Audit Standard
Every finding in this audit series is documented under a strict 9-point evidentiary template:
1. Feature/module name
2. Expected behavior
3. Actual implementation status
4. Evidence (file path, function/class/component, API route, database table, test result)
5. Status (`FULLY IMPLEMENTED`, `PARTIALLY IMPLEMENTED`, `PROTOTYPE ONLY`, `MOCKED`, `BROKEN`, `UNSAFE`, `NOT TESTED`, `NOT IMPLEMENTED`)
6. Severity (`P0 Critical`, `P1 High`, `P2 Medium`, `P3 Low`)
7. Recommended fix
8. Dependencies
9. Acceptance criteria

Under this standard, zero UI screens are assumed to imply backend existence without verified endpoints, database models, and automated test coverage.
